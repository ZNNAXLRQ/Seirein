# Seirein

> 基于 DeepSeek Harness（DSH）实现的 Nano 版类 Neuro 多模态助手插件，尝试实现可能没那么智能的基本功能：语音输入、语音输出、人设维持、长期记忆、视觉与听觉、Live2D 形象驱动、字幕展示，以及DSH本身具有的各种功能。

| 名称 | 具体内容 |
| --- | --- |
| 包名 | `@local/dsh-assistant` |
| 插件 id | `dsh-assistant` |
| 版本 | `0.99.0` |
| 宿主 | DeepSeek Harness（DSH）Desktop，Host 运行在 Node 模式子进程 |
| 平台 | Windows（依赖 PowerShell / WPF / DPAPI / DirectShow） |
| 许可证 | MIT |

项目目前还在长期使用测试阶段，欢迎提出反馈，开发和维护看空闲进行

## 1. 项目简介与参考对象

### 1.1 Seirein 是什么

Seirein 是 DSH 的一个 **bundle 插件**（不是独立应用）：它随 DSH 启动，把自己注册进宿主进程，向外提供 24 个工具、一套 HTTP 设置接口和一个 Web 设置页。

它将 DSH 变成了一个多模态助手, 完成了「把一个能听见、能看见、有人设、有记忆、有形象、会说话、能做事的桌面助手装进 DSH」这件事，而不只是再造一个语音聊天前端。DSH 负责模型、会话、工具循环与 Agent 生命周期；Seirein 负责把语音、感知、形象与人设接到这条循环上。

必须知道的运行边界：

- **Host 是 Node 模式子进程**，拿不到 Electron API（`BrowserWindow`、`globalShortcut`、`Tray` 都不可用）。因此字幕、透明层、窗口几何走 PowerShell / WPF，热键走 `koffi` 轮询 Win32，形象走 VTube Studio WebSocket，配音走 Edge TTS 或本机 GPT-SoVITS HTTP 服务。
- **插件不 import 任何 Harness 包**，只通过宿主注入的 `ctx` 服务工作：工具注册、会话事件、`agent/pre-step`、`webServer`、客户端 slots、Agent preset 注册表等。
- **Windows 专属实现很多**：麦克风枚举与采集、DPAPI 凭据、Windows 字体枚举、WPF 叠加层、窗口矩形读取。非 Windows 环境至少语音 / 视觉 / 字幕链路不可用。
- **一个进程内的一套状态**：插件卸载或 DSH 重启后语音、采集、字幕、形象进程都会重建；数据保留在 `<root>` 下。

### 1.2 功能模块

`src/host` 根目录只有 `index.js`，实现按功能域分目录；`client.js` 在仓库根（DSH 会缓存客户端入口路径）。

| 模块 | 目录 | 职责 | 对外表现 |
| --- | --- | --- | --- |
| 语音 | `speech/` | TTS（Edge / GPT-SoVITS）、翻译双流、口语版、候音、播放账本、分块与预取 | 「说」：回答、候音、工具播报、打字回合播报 |
| 听觉 | `hearing/` | 麦克风 / 回环采集、ASR worker、VAD、端点、声纹影子、通话模式、环境音、音频保留 | 「听」：实时转写、连续对话缓冲、打断判定 |
| 记忆 | `memory/` | 分域情节记忆（SQLite + FTS5）、固定记忆、自动记录、召回 / 纠正 / 归档 / 容量衰退 | 「记得」：相关记忆、固定约束、历史检索 |
| 视觉 | `vision/` | 截图、故事板、桌面 / OBS 虚拟摄像头、隐私锁、OBS 连接、黑帧检查 | 「看见」：按需截屏、连续观看、场景查看 |
| 形象动作 | `avatar/` | VTS 连接 / 热键 / 表情 / 口型 / 参数、行为运行时、动作预设库、WPF 透明层、Spout 独立进程 | 「动」：说话口型、语义动作、待机生命感 |
| 字幕 | `subtitle/` | WPF 叠加层、区域 / 气泡模式、字体枚举、对比色、分页 | 「显示」：语音字幕与原文对照 |
| 平台 | `platform/` | 全局热键（`koffi`）、硬件探测、模型下载、Windows 窗口矩形 | 系统层适配 |
| 运行时 | `runtime/` | 组件开关、依赖引用计数、工具执行、HTTP、诊断、关闭编排 | 插件骨架与可观测性 |
| 会话 | `session/` | 投递与结果绑定、快路 / 轻量模型通道、请求前上下文、连续台词、待回应组、日切、压缩 | 与 DSH Agent 的接缝 |
| 画像 | `profile/` | 人设与用户画像、画像库分类 / 评分 / 整理、初始问卷 | 长期人设与偏好 |
| 共享 | `shared/` | 纯文本与时间函数 | 跨域复用，不持有状态 |

组件开关（`data/features.json`，不是 `cordis.patch.yml`）共 8 个，默认值如下：

| id | 名称 | 默认 | 作用 |
| --- | --- | --- | --- |
| `hearing` | 听觉 | 开 | 麦克风采集与流式识别 |
| `ambient` | 环境声音 | 开 | 回环端点采集，只作上下文，不触发回复 |
| `voice` | 语音合成 | 开 | 让助手出声；关闭后只输出文字 |
| `vision` | 视觉 | 开 | 截图与故事板 |
| `subtitle` | 字幕显示 | 开 | 屏幕叠加字幕 |
| `avatar` | 形象 | 开 | VTS 表情 / 口型 / 动作 |
| `memory` | 记忆 | 开 | 记忆读写与检索 |
| `fastpath` | 闲聊模式 | **关** | 绕过 agent、直连 LLM 的纯闲聊通道 |

工具面共 **24 个**（`test/smoke.mjs` 会断言数量）：

| --- | --- |
| 语音 / 听觉 | `assistant_say`、`assistant_listen`、`assistant_ambient`、`assistant_call_mode` |
| 视觉 | `assistant_see`、`assistant_watch`、`assistant_vision`、`assistant_obs`、`assistant_obs_status` |
| 形象 | `assistant_live2d`、`assistant_hotkeys` |
| 记忆 / 画像 | `assistant_remember`、`assistant_recall`、`assistant_memory_brief`、`assistant_memory_correct`、`assistant_archive_search`、`assistant_resource_set/get/list/forget`、`assistant_persona_view/append`、`assistant_prompt_preview` |
| 运行时 | `assistant_doctor` |

### 1.3 实现了什么效果

以下描述的功能都能在代码、事件日志或测试里找到对应，是目前认为确定实现的功能。

| 效果 | 实际行为 | 可核对位置 |
| --- | --- | --- |
| 语音对话闭环 | 说完一句 → ASR 终稿 → 投递到当天的 `seirein-YYYY-MM-DD` 会话 → Agent 回答 → 自动生成口语版 → TTS 播放，字幕与口型跟随同一句音频 | `voice.injected`、`voice.reply`、`voice.first-sentence` 事件 |
| 可打断 | 默认只允许**通过校验的成句 final** 停播；单个 partial、咳嗽、回声、重复句不会打断。`voice.bargeInPartial` 是可选项，开启后才接受连续响亮 partial | `hearing.bargein`、`hearing.bargein.skipped` |
| 候音 | 用户消息投递后计时，默认 **3000 ms**（可在 500–15000 ms 调）回答仍未出声，就说一句简短等待语；正文音频就绪时未播放的等待语会被取消 | `voice.ack.*` 事件 |
| 一次只播一个版本 | 短答原样播；长答最多一次轻量模型改写为口语版；改写失败回落**完整正文**，不截断成摘要 | `voice.spoken.version` |
| 压缩上下文 | 当天语音会话挂载只含压缩能力的 `seirein-voice` preset；接近窗口 80% 时置 `near-limit` 并写节流事件 | `voice.compaction.*` |
| 动作预设 | 动作库按状态 / 事件 / 语义 / 已验证通道硬过滤，设置页可禁用、调优先级、恢复默认；不可用项跳过而不是降级成热键 | `motion.presets.*`、`avatar.*` |
| 视觉观看 | 桌面用 ffmpeg ddagrab（gdigrab 兜底）；场景模式读 OBS 虚拟摄像头；`assistant_watch` 把 4–8 个变化帧拼成一张故事板；隐私模式下所有 agent 捕获被拒绝 | `assistant_see` / `assistant_watch` / `vision.*` 事件 |
| 字幕 | 区域模式或气泡模式（跟随统一形象几何）；字幕语言与语音语言独立 | `subtitle.*` 事件 |
| 记忆 | 相关记忆在 `agent/pre-step` 注入；固定记忆每轮注入（加密项只给索引）；普通记忆按容量衰退并归档 | `memory.recall`、`resource.inject.truncated`、`memory.*` |
| 设置页 + 热键 | 插件页 / 设置分区里可切换组件、设备、语种、TTS、字幕、VTS、热键、记忆、人设；默认热键 `Ctrl+Alt+M`（麦克风）、`Ctrl+Alt+V`（视觉）、`Ctrl+Alt+E`（图层编辑）、`Ctrl+Alt+A`（环境音） | `client.js`、`assistant_hotkeys` |

## 2. 针对用户的简单使用说明

> 这一章只讲「怎么装、要准备什么、点哪里、坏了怎么办」。不需要懂代码；看到路径或英文提示，照着做即可。
> 开发者的本地目录安装、配置键和调试方法放在每节末尾的折叠块里，普通用户可以跳过。

**建议按这个顺序走：**

1. 先装插件（2.1）。
2. 第一次打开设置页，选「存放位置」（2.3.1）。
3. 放好 FFmpeg 和语音模型（2.2、2.3.2）。
4. 试麦克风，能出字了再开 TTS / 字幕（2.3.3–2.3.5）。
5. 想要形象或场景视觉，再按需装 VTS、OBS、VB-Cable（2.2、2.4）。

---

### 2.1 插件怎么安装

Seirein 是 DSH 的**插件**，不是独立软件。装好 DSH Desktop 后，在 DSH 里安装它。

#### 2.1.1 先确认三件事

1. 系统是 **Windows 10 / 11 x64**。语音、视觉、字幕依赖 Windows 的 PowerShell / WPF / DirectShow，其它系统用不了这些功能。
2. 已经装好 **DSH Desktop** 并能正常打开。DSH 的官方地址：<https://github.com/deepseek-ai/deepseek-harness>；桌面版安装包在 <https://github.com/deepseek-ai/deepseek-harness/releases>。
3. 电脑能上网。安装依赖、Edge TTS、第一次下载 VAD 模型都需要网络。

安装本身**不需要**你装 Node.js、pnpm，也不需要开命令行。DSH 会处理依赖。

#### 2.1.2 最省事：两种方式二选一

**方式 A：Release 压缩包（推荐，版本固定）**

适合：不想装 git、希望以后能重复装同一个版本的人。

1. 打开 <https://github.com/ZNNAXLRQ/Seirein/releases>。
2. 下载名字类似 `local-dsh-assistant-0.99.0.tgz` 的文件。
3. 把它放到一个**以后不会移动、不会删除**的文件夹。DSH 会记住这个文件的路径；以后移动或删掉它，重装/更新可能失败。
4. 在 DSH 侧栏点 **插件** → **添加插件**。
5. 在输入框里填这个 `.tgz` 文件在**这台电脑上的完整路径**（例如 `C:\Users\<你>\Downloads\local-dsh-assistant-0.99.0.tgz`）。
   - 这里没有「上传文件」按钮，必须填 Host 电脑上的路径；如果你是从另一台电脑远程打开 DSH，路径仍要写 DSH 所在电脑的路径。
6. 点 **安装**，等它跑完。

**方式 B：Git 地址（少下载一步，但需要 git）**

适合：电脑已经装了 git，想直接装仓库最新提交的人。

1. 确认电脑上有 git：打开「终端 / PowerShell」，输入 `git --version`，能看到版本号即可。
2. 在 DSH 侧栏点 **插件** → **添加插件**。
3. 填仓库地址：`https://github.com/ZNNAXLRQ/Seirein.git`。
4. 点 **安装**，等它跑完。

两种方式的区别：

- **Release 压缩包**：装的是你下载的那个版本，稳定、可复现；缺点是文件要放在固定位置。
- **Git 地址**：装的是远端默认分支**当时最新的一次提交**；不会包含本机未提交的改动，以后也不会自动更新。要固定版本，请在地址后加 `#<提交号或标签>`（这是开发者用法）。
- 当前**没有发布到 npm**，所以不要输入 `@local/dsh-assistant` 之类的包名去装，会装不到。

#### 2.1.3 允许依赖脚本（第一次安装几乎都会遇到）

安装过程中可能出现类似提示：

```text
[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: koffi@3.1.1, msedge-tts@2.1.1
```

这不是 Seirein 自己要编译，而是包管理器默认不运行依赖的安装脚本。`koffi` 用来读 Windows 快捷键，`msedge-tts` 用来调用 Edge 语音。

1. 在失败提示里找 **「允许这些脚本并重试」**（英文界面可能是 **Approve builds and retry**）。
2. 点它，等安装完成。
3. 如果界面没有这个按钮：先把 DSH 更新到较新版本；仍没有就卸载后重新安装一次。
4. 不要点「忽略」。忽略后安装会以失败结束，插件不会出现在列表里。

`koffi` 使用的是预编译文件，不需要你装 C++ 编译工具。

#### 2.1.4 立即启用，然后重启

1. 安装成功后，插件页会出现 **Seirein**。
2. 如果按钮写着 **立即启用**，点它；如果只有一个开关，把开关打开。
3. 按提示**重启 DSH**。第一次安装、更新、改过插件配置之后都建议重启；只刷新网页不算重启。
4. 重启后回到 **插件** 页，确认 Seirein 仍是「已启用」。

**什么时候需要重启：**

- 第一次安装：需要。
- 更新插件 / 卸载重装：需要。
- 改过插件配置文件（高级）：需要。
- 只在设置页里改选项：大多数不用重启；改「存放位置」必须重启 DSH。
- 页面显示旧内容：先刷新页面（`Ctrl+R`）；还旧就重启 DSH。

#### 2.1.5 装好后怎么确认成功

按顺序看四件事：

1. **插件页**里能看到 Seirein，状态是「已启用」。
2. 打开 Seirein 的设置页，最上面的 **Seirein** 卡片显示「客户端 / 服务端 v0.99.0」和一个「根目录」。
3. 第一次进入时，页面顶部有 **「首次使用：请先选择存放位置」** 卡片。
4. 「听觉」卡片里能点 **测试麦克风**。这时点不一定成功：缺 FFmpeg 或语音模型会给出明确提示，按提示去 2.2 补。

如果第 1 步就看不到 Seirein，直接看 2.6.1。

#### 2.1.6 以后怎么更新

- **压缩包方式**：插件页打开 Seirein → 先卸载 → 再用新 `.tgz` 安装 → 启用 → 重启 DSH。
- **Git 地址方式**：先卸载 → 再添加同一个地址 → 启用 → 重启 DSH。它不会自己更新。
- 更新插件**不会删除**你的数据；数据在「数据根」里，见 2.5.7。
- 更新后如果页面还显示旧版本，先刷新页面，再重启 DSH。

### 2.2 需要下载 / 准备什么

先把「数据根」认准，下面所有路径都以它为基准。

#### 2.2.1 先认准「数据根」

- 默认数据根：`%LOCALAPPDATA%\Seirein`（通常就是 `C:\Users\<你>\AppData\Local\Seirein`）。
- 如果你在设置页选了父目录（例如 `D:\SeireinData`），数据根是 **`D:\SeireinData\Seirein`**，不是 `D:\SeireinData` 本身。
- 本文用 **`<数据根>`** 代表这个目录。它下面会有：

```text
<数据根>\
  bin\        ffmpeg.exe / ffplay.exe（你自己放）
  models\     语音识别、VAD、声纹模型
  data\       设置、组件开关、事件日志
  memory\     记忆库、人设、画像、声纹库
  cache\      临时音频、截图、字幕缓存（可以删）
  workspace\  助手会话的工作目录
```

#### 2.2.2 先分清「谁负责下载」

- **安装插件时自动装好的**：运行库 `sherpa-onnx-node`、`koffi`、`msedge-tts`、`ws` 等。你只需要在安装时点一次「允许依赖脚本」。
- **插件运行时自动下载的**：
  - Silero VAD（第一次开麦时，下到 `<数据根>\models\silero_vad.onnx`）。
  - CAM++ 声纹模型（你打开「声纹影子」后，下到 `<数据根>\models\`）。
- **必须你自己放的**：FFmpeg、流式 ASR 模型、精识别模型（推荐）、OBS / VTS / VB-Cable / GPT-SoVITS（按需）。
- 插件**不会**自动下载 FFmpeg 和 ASR 模型；不要等它自己下。

#### 2.2.3 Windows 环境（必需）

- **Windows 10 / 11 x64**。
- 需要系统自带的 PowerShell、WPF、DPAPI、DirectShow。它们通常都在；被精简过的系统可能缺。
- 这个插件必须在 **Windows 上的 DSH** 里运行；语音、视觉、字幕在 macOS / Linux 上不可用。
- 不需要额外安装 Node.js，DSH 自带运行时。

**没满足会怎样：** 插件能装上，但麦克风、截图、字幕、透明层会失败或完全不可用。

#### 2.2.4 FFmpeg（必需）

**作用：** 麦克风 / 回环采集、截图、故事板、音频转码；如果同目录有 `ffplay.exe`，也用它播放语音。

**下载（任一即可）：**
- BtbN 的 Windows 构建（推荐，bin 较新）：<https://github.com/BtbN/FFmpeg-Builds/releases> → 选 `win64-gpl` 压缩包 → 解压。
- gyan.dev 的 Windows 构建：<https://www.gyan.dev/ffmpeg/builds/> → 选 `full`（确保含 `ddagrab` 桌面采集）。
- 包管理器：`winget install Gyan.FFmpeg`。

**验证：** `ffmpeg -version` 正常输出；`ffmpeg -filters | findstr ddagrab` 能看到 `ddagrab`（视觉桌面采集需要）；`ffmpeg -list_devices true -f dshow -i dummy` 能看到麦克风/回环设备。

**放到哪里（三选一）：**

1. 最简单：把 `ffmpeg.exe` 放到 **`<数据根>\bin\ffmpeg.exe`**；最好把 `ffplay.exe` 也放在同一个 `bin` 目录。
2. 设环境变量 `DSH_FFMPEG_PATH`，值指向 `ffmpeg.exe` 的完整路径。
3. 高级：在插件配置里写 `ffmpegPath`。

**特别注意：** 插件**不会**从系统 `PATH` 里找 ffmpeg。即使你在命令行里能运行 `ffmpeg`，插件仍可能报「未找到 ffmpeg」。必须放到上面三个位置之一。

**怎么验证：**

1. 设置页 → **听觉** → **测试麦克风**。
2. 如果报「未找到 ffmpeg」，说明路径不对，按上面重放。
3. 设置页 → **视觉与隐私** → **截图测试**；能看到「最近取景」缩略图就说明视觉也能用。

**没放会怎样：** 听觉、环境声音、截图、故事板都不可用。语音合成可能仍能出声（会退回 WPF 播放），但采集链路无法工作。

#### 2.2.5 流式 ASR 模型（必需）

**作用：** 边说边出字、判断一句话说完了、把话投递给助手。

**下载：** 直接下载 <https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-streaming-zipformer-zh-14M-2023-02-23.tar.bz2>（`asr-models` 发布里的精确附件名；同页还有 `-mobile` 版本，桌面端用这个非 mobile 版）。解压后把目录内容放到 `<数据根>\models\stream`。

**放到哪里：** 解压后放到

```text
<数据根>\models\sherpa-onnx-streaming-zipformer-zh-14M-2023-02-23\
```

这个目录里必须能直接看到这 4 个文件：

```text
encoder-epoch-99-avg-1.onnx
decoder-epoch-99-avg-1.onnx
joiner-epoch-99-avg-1.onnx
tokens.txt
```

解压后通常会多一层同名文件夹；请把**里面的文件**放到上面的目标目录，不要变成「目录里再套一层同名目录」。

**自定义目录（高级）：** 插件配置 `asrModelDir`。改到自定义目录后，VAD 模型不会再自动下载，见 2.2.7。

**怎么验证：** 设置页 → 听觉 → 测试麦克风。如果报 `ASR 模型缺失：<某个路径>`，就按那个路径检查上面 4 个文件。

**没放会怎样：** 听觉启动直接失败，环境声音也无法启动。这是最常见的「麦克风没反应」原因之一。

#### 2.2.6 精识别模型（可选，但强烈推荐）

**作用：** 一句话说完后，再用更准的模型重新识别一遍终稿；标点、数字、专有名词会更稳，也支持中 / 英 / 日 / 韩 / 粤。

**下载：** 和流式模型同一个 `asr-models` 发布页，精确附件名 `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2`：
<https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17.tar.bz2>
（想要更小可用同页 `...-int8-2024-07-17.tar.bz2`）。解压后放到 `<数据根>\models\final`。

**放到哪里：**

```text
<数据根>\models\sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17\
```

目录里至少要有：

```text
model.int8.onnx
tokens.txt
```

**自定义目录（高级）：** 插件配置 `asrFinalModelDir`。

**怎么验证：** 它没有单独的开关或状态灯。只要听觉能启动，就说明「不装也能用」；装好后终稿质量会变好。是否真的用上，属于高级排查，普通用户不用管。

**没放会怎样：** 仍能听说，但终稿直接使用流式结果，准确率和标点会下降；不会阻止插件启动。

#### 2.2.7 VAD 模型（插件自动下载）

**作用：** 判断「现在有没有人说话」「一句话什么时候结束」，也就是端点检测。

**谁负责：** 插件自动下载，不需要你找。

- 第一次开麦时，如果模型目录还是默认的 `<数据根>\models\...`，插件会把模型下到 **`<数据根>\models\silero_vad.onnx`**（约 0.6 MB）。
- 下载地址（插件内部使用）：<https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/silero_vad.onnx>
- 下载失败不会阻止采集：插件会退回按音量判断端点，效果差一些，日志里会出现 `hearing.vad.unavailable`。

**什么时候要自己放：** 如果你把 `asrModelDir` / `asrFinalModelDir` 改到了非默认目录，自动下载不再生效；此时需要把 `silero_vad.onnx` 放到那个模型目录的**上一级目录**（默认就是 `<数据根>\models`）。

**没下到会怎样：** 还能说话，但「说完没有」「什么时候算一句」的判断会变差，可能出现半句就投递或迟迟不结束。

#### 2.2.8 语音合成 TTS（内置 Edge，需要网络）

**作用：** 让助手出声。默认使用 **Edge TTS**（`msedge-tts`）。

- **不需要安装额外软件，不需要 API Key。**
- 但它调用的是微软 Edge 的**在线朗读服务**，所以**必须联网**；它不是 Windows 自带的系统语音，断网时不会自动改成离线系统声音。
- 默认声音按语种选择：中文 `zh-CN-XiaoxiaoNeural`、日语 `ja-JP-NanamiNeural`、英语 `en-US-AriaNeural`、韩语 `ko-KR-SunHiNeural`、粤语 `zh-HK-HiuGaaiNeural`。想换声音用高级配置 `ttsVoice`；设置页没有声音下拉框。
- 播放时如果同目录有 `ffplay.exe`，优先用 ffplay；没有就退回 PowerShell / WPF 播放，仍能出声，只是启动稍慢。

**可选：** 想用本地音色 / 克隆音色，再装 GPT-SoVITS，见 2.2.12。GPT-SoVITS 失败时会自动回退到 Edge。

**没网 / 被拦截会怎样：** 没有声音；文字和字幕仍正常。可以换网络、开代理，或改用本地 GPT-SoVITS。

#### 2.2.9 OBS Studio（可选）

**作用：** 让助手看 OBS 里的某个场景（通过 OBS 虚拟摄像头），以及可选的场景切换。桌面视觉不需要 OBS。

**下载：** <https://obsproject.com/>。建议 OBS 30 或更新版本（自带 WebSocket 5.x）。

**安装：** 用默认安装即可。插件不附带 OBS，只会在需要时连接它。

**没装会怎样：** 仍然可以用「桌面（屏幕）」视觉；只是不能看 OBS 场景。

#### 2.2.10 VTube Studio（可选）

**作用：** Live2D 形象、口型、表情、动作。

**下载：** <https://denchisoft.com/>；Steam 页面：<https://store.steampowered.com/app/1325860/VTube_Studio/>。

**要求：** VTS 里打开 API（默认端口 8001），加载一个模型；想让形象浮在桌面上，还需要 VTS 的背景是透明的，左侧栏选择背景，找到ColorPicker，颜色输入#FF00FF，打开下方透明推流按钮。

**没装会怎样：** 只有声音和字幕（仍可以使用区域模式），没有 Live2D 形象；其它功能不受影响。

#### 2.2.11 VB-Audio Virtual Cable（可选）

**作用：** 当电脑没有「立体声混音」时，给「环境声音」提供一个回环端点，让助手听到电脑正在播放的声音。

**下载：** <https://vb-audio.com/Cable/>。安装后建议重启一次。

**怎么用：** 设置页 → 环境声音 → 回环设备选 `CABLE Output`。如果想让 OBS 的声音也进来，在 OBS 里把「监视设备」设为 `CABLE Input`。

**没装会怎样：** 如果系统本来就有「立体声混音」，仍可用；两者都没有时，环境声音无法启动。

#### 2.2.12 GPT-SoVITS（可选）

**作用：** 本地语音合成、音色克隆，替代或补充 Edge TTS。

**下载：** <https://github.com/RVC-Boss/GPT-SoVITS>。按官方说明准备 Python 环境和模型；体积通常有几个 GB。

**运行：** 启动它的 `api_v2.py` HTTP 服务，默认地址 `http://127.0.0.1:9880`。有独立显卡更流畅（约占 3–4 GB 显存）；纯 CPU 也能跑，但慢。

**插件只通过 HTTP 连接它**，不会替你装 Python、下载权重或启动服务（除非你在「连带启动」里配置）。

**没装会怎样：** Edge TTS 已经够用；不装不影响其它功能。

#### 2.2.13 声纹模型 CAM++（可选，默认关）

**作用：** 给麦克风里的一句话打一个「像不像同一个人」的分数，只做记录，不拦截、不改写、不进记忆。

**谁负责：** 你打开「声纹影子」后，插件自动下载到（前提是仍使用默认的 `<数据根>\models\...` 模型目录）：

```text
<数据根>\models\3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx
```

约 27 MB。来源：<https://github.com/k2-fsa/sherpa-onnx/releases/download/speaker-recongition-models/3dspeaker_speech_campplus_sv_zh-cn_16k-common.onnx>

**限制：** 只对麦克风通道生效；回环（电脑播放的声音）默认不跑声纹，避免把混合声音认成你。

**代价：** 多一次 CPU 推理、首次要下载模型；声纹库为空时会显示「无声纹」。

**没开 / 没下到会怎样：** 完全不影响听、说、记忆和投递；只是没有声纹判定。

#### 2.2.14 推荐准备顺序

1. 放好 FFmpeg（2.2.4）。
2. 放好流式 ASR 模型（2.2.5）和精识别模型（2.2.6）。
3. 安装并启用插件（2.1）。
4. 第一次开麦，让插件自动下 VAD（2.2.7）。
5. 按需再装 OBS / VTS / VB-Cable / GPT-SoVITS。

### 2.3 必须做的设置（按顺序）

所有设置都在 **Seirein 的设置页**：DSH 侧栏 **插件** → **Seirein** → 打开设置。设置页从上到下排列，下面按顺序走一遍即可。

先记住一件事：**「组件开关」是总许可，打开不等于马上开始录音或截图。**
听觉要你点「测试麦克风」或打开「开机自动监听」才会开始采集；视觉要你点「截图测试 / 启动持续观看」才会取景。

#### 2.3.1 存放位置（第一次必须做）

**在哪里：** 设置页最上面的 **「首次使用：请先选择存放位置」** 卡片。

**怎么做：**

1. 点 **选择存放位置**。
2. 选一个空间足够的目录，例如 `D:\SeireinData`。
3. 页面会提示数据会放到 `<所选目录>\Seirein`。确认后保存。
4. 看到「保存后需重启 DSH 生效」的提示。
5. 重启 DSH。
6. 重新打开设置页，看最上面的 **Seirein** 卡片：「根目录」已经变成新路径，首次提示消失。

**想用默认位置：** 点卡片上的 **使用默认位置** 即可，数据在 `%LOCALAPPDATA%\Seirein`。

**怎么算成功：** 重启后「根目录」显示你选的路径，且该目录下出现 `data`、`memory` 等文件夹。

**没设置会怎样：** 数据会先写在默认目录；「首次使用」提示会一直挂着。以后再去改位置，**不会自动把旧位置的数据搬过去**。

**注意：**

- 选好之后不要手动剪切/移动这个文件夹；要换位置请回到设置页改，然后重启。
- 如果以前用过旧的默认目录 `%LOCALAPPDATA%\dsh-assistant`，插件在新根第一次解析时会尝试一次性复制 `memory`、`data`、`cache`、`models`、`vts-token.json`；原目录不会被删除。

#### 2.3.2 麦克风设备与门限

**在哪里：** 设置页 → **听觉** 卡片。

**怎么做：**

1. 点「输入设备」旁的 **刷新**。
2. 在下拉框里选你真正在用的麦克风。
   - 「立体声混音」「CABLE Output」等回环设备会显示为灰色，写着「回环输入，不可选」。这是故意的，避免助手把自己的声音再听回去。
3. 点 **测试麦克风**。
4. 看状态变成「监听中 · 设备名 · xx dB」。
5. 对着麦克风说话，看 dB 数值是否跟着跳动。
6. 说完停顿约 1.2 秒，看是否出现识别文字（终稿）。

**门限怎么调：**

- 「阈值」默认是 **-50 dB**。数值**越低越敏感**，越高越不敏感。
- 环境吵、总被键盘/风扇触发：往上调，例如 `-40` 或 `-35`。
- 说话声音小、总是没反应：往下调，例如 `-55` 或 `-60`。
- 允许范围是 **-90 到 -10**。
- 保存后如果采集正在运行，插件会重启采集；看到「已生效（新实例）」才算真正生效。

**怎么算成功：** 说话时 dB 明显变化，停顿后能出字。只有 dB 动、没有字，通常是模型或语种问题，见 2.6.4 / 2.6.5。

**没设置会怎样：** 可能选到错误设备、一直没反应，或者环境声不断触发；回环设备被拒绝是为了防止回声。

#### 2.3.3 语音 / 字幕语言

**在哪里：** 设置页 → **语种** 卡片。

**怎么做：**

1. 「语音语种」选助手说话用的语言：中文 / 日语 / 英语 / 韩语 / 粤语。
2. 「字幕语种」选字幕显示用的语言，可以和语音不同。
3. 改完立即保存；不需要重启。

**怎么算成功：** 让助手说一句话，听到的语言和字幕语言分别符合设置。

**没设置会怎样：** 默认都是中文。你对它说日语、却把语种留在中文，识别和朗读都会不对。

**两者不同会怎样：** 助手会把「说的文本」和「字幕文本」分开处理；这是给翻译字幕用的，普通用户保持相同即可。

#### 2.3.4 人设与用户画像（最少要填什么）

**在哪里：** 设置页 → **人设库 · N/M** 卡片（在记忆卡片下面）。

**怎么做：**

1. 在 **人设（她是谁、怎么说话）** 框里写 3–5 句：她叫什么、是什么身份、用什么语气、怎么称呼你、绝对不要做什么。
2. 在 **画像（稳定的偏好与事实）** 框里写 2–3 条：你的称呼、常用语言、作息、喜欢/讨厌的东西、禁忌。
3. 点 **保存**。
4. 看到「已保存到文本框……」的提示，说明已经生效；人设和画像会立即用于下一轮对话。
5. 想让内容进入「人设库」做分类，再点 **整理后入库**（或 **立刻整理**）。这一步是可选的。

**完全不知道怎么写：** 点 **生成初始人设**，站在助手的角度完成你期望的回答，题目全部可选，作答完成大模型会分析答案生成一份草案；用户可以改，再点保存或正式采用，没测试过性能如何，生成结果仅供参考。

**怎么算成功：** 新开一轮对话，助手用你写的称呼和语气回应；你说「记住我喜欢……」时，记忆也会按画像走。

**没设置会怎样：** 助手只有默认语气，不会用你期望的称呼；记忆仍然工作，但缺少个性化背景。

**注意：**

- 「保存」只写入文本框，不等于入库；「整理后入库」才会拆分分类。但是生效按框内容生效，意味着哪怕不入库只要写了就会生效。
- 自动整理默认每 7 天一次、空闲时进行；可以在卡片里暂停。
- 人设文件在 `<数据根>\memory\persona.md`，画像在 `<数据根>\memory\user.md`。
- 人设整理需要较长的时间，涉及到对现有内容的分析整理与人设重写，请耐心等待。

#### 2.3.5 TTS 引擎与声音

**在哪里：** 设置页 → **语音合成** 卡片。

**怎么做（默认 Edge，最省事）：**

1. 确认「语音播报」是 **已开启**。
2. 不需要填任何东西。默认就是 Edge TTS，按 2.3.3 的语音语种自动选声音。
3. 让助手说一句话（语音或打字都行），听到声音即成功；字幕应与声音同步。

**想用 GPT-SoVITS 音色：**

1. 先按 2.2.12 装好并启动 GPT-SoVITS 的 API 服务。
2. 打开「使用 GPT-SoVITS 音色」。
3. 填 **API 地址**（默认 `http://127.0.0.1:9880`）。
4. 填 **参考音频路径**（3–10 秒的干净人声）和 **参考文本**（音频里说的那句话）。
5. 如果要加载自己的权重，填 **GPT 模型** / **SoVITS 模型** 路径，然后点 **应用模型**；只填路径不会加载。
6. 说一句测试；失败会自动回退 Edge。

**怎么算成功：** 听到声音，且音色符合预期。

**没设置 / 失败会怎样：**

- 「语音播报」关掉：只出文字，没有声音。
- Edge 没网或被拦截：静音；可换网络或改用 GPT-SoVITS。
- GPT-SoVITS 没启动：自动回退 Edge，不会一直哑着。
- 所有播报共用一个队列，同一时刻只播一句；上一句没播完时，新的一句要排队。

**注意：** GPT-SoVITS 第一次加载模型可能很慢（默认超时 30 秒）；别把它当成故障，等一次或调大超时。

#### 2.3.6 视觉来源（桌面 / OBS）

**在哪里：** 设置页 → **视觉与隐私** 卡片。

**怎么做（桌面，最简单）：**

1. 「选择观看来源」选 **桌面（屏幕）**。
2. 点 **截图测试**。
3. 看下方是否出现「最近取景」缩略图和尺寸。
4. 想让助手持续看，点 **启动持续观看**；再点一次停止。

**怎么做（OBS 场景）：**

1. 先按 2.4.1 配好 OBS。
2. 「选择观看来源」下拉里选一个 OBS 场景（没有就先点 **刷新场景**）。
3. 点 **截图测试** 或 **启动持续观看**。
4. 看缩略图是否是该场景，而不是黑屏。

**怎么算成功：** 缩略图出现且内容是你要看的画面。

**没设置会怎样：** FFmpeg正常的时候只能看桌面；如果 FFmpeg 没放好，截图和观看都会失败。选了 OBS 但 OBS 没开/没虚拟摄像头，也会失败，不会偷偷用桌面顶替。

**隐私按钮：** 卡片里的 **切换隐私模式** 是给用户用的；开启后两种来源都停，助手不能自己退出，详见 2.5.1。

#### 2.3.7 VTS 连接（要形象才做）

**在哪里：** 设置页 → **形象** 卡片。

**怎么做：**

1. 打开 VTube Studio，加载一个 Live2D 模型。
2. 在 VTS 设置里开启 API，端口保持默认 **8001**。
3. 回到 Seirein 设置页 → 形象 → 点 **连接 VTS**。
4. VTS 会弹出授权窗口；点允许。超过约 60 秒不点会超时。
5. 状态变成「已连接 · 模型名」。
6. 点 **测试连接**，会触发当前模型的第一个热键；模型动一下即成功。

**想让形象浮在桌面上：** 在形象卡片下方打开 **桌面悬浮 / 开启透明层**；VTS 的背景需要是透明的。第一次用可以点 **编辑模式** 拖动/缩放，再点 **完成编辑**。

**怎么算成功：** 状态「已连接」，测试热键有反应，说话时口型跟着动。

**没设置会怎样：** 没有 Live2D 形象和口型；声音、字幕、视觉仍然可用。

**注意：** 动作/表情依赖模型自己的参数、热键和表情。名字对不上或没有映射的部位会被跳过，不会硬触发一个不存在的动作。

#### 2.3.8 全局热键（建议检查一次）

**在哪里：** 设置页 → **全局快捷键** 卡片。

**默认四组：**

- `Ctrl+Alt+M`：开 / 关麦克风（静音 / 恢复）。
- `Ctrl+Alt+V`：开 / 关隐私模式（只由用户操作）。
- `Ctrl+Alt+E`：形象编辑模式。
- `Ctrl+Alt+A`：开 / 关环境声音。

**怎么改：**

1. 找到要改的一项，点 **改键**。
2. 按下新的组合键（主键盘字母/数字必须带 Ctrl / Alt / Shift / Win 之一；F 键或媒体键可以单按）。
3. 点 **保存**，看到「已改绑」。
4. 想恢复默认，点 **重置**。

**怎么算成功：** 按一下热键，对应状态变化（麦克风开始/停止、隐私锁定/退出等）。

**没设置会怎样：** 默认热键仍然可用；如果和别的软件冲突，按上面的步骤改掉即可。小键盘键需要 NumLock 打开。

### 2.4 选了可选项后要补的设置

这一节只在你要用对应功能时看；不用就跳过。

#### 2.4.1 OBS（场景视觉 / 虚拟摄像头）

**先装好并打开 OBS。** 然后在 OBS 里：

1. 打开 **工具 → WebSocket 服务器设置**（不同版本文字略有差异）。
2. 确认端口是 **4455**。
3. 建议**关闭认证**（不要设密码）。插件默认按「4455 + 无密码」连接。
4. 点「启动虚拟摄像头」一次，确认系统里有 `OBS Virtual Camera` 这个设备。

**回到 Seirein：**

1. 设置页 → 视觉与隐私 → 点 **刷新场景**。
2. 在下拉里选一个场景。
3. 点 **截图测试**；如果黑屏，先确认 OBS 虚拟摄像头已启动、场景里有画面。

**端口 / 密码不是默认值怎么办：**

- 设置页**没有** OBS 端口和密码输入框。
- 插件配置里有 `obsPort`（默认 `4455`）和 `obsPassword`（默认空）。改完需要重装/重启插件。
- 普通用户最省事：把 OBS 恢复成 4455、关闭认证。
- 如果 OBS 开了密码但插件没配，会报「OBS 需要密码，但配置里没有 obsPassword」。

**虚拟摄像头名不是默认值：** 插件默认找 `OBS Virtual Camera`；如果你改过名字，用高级配置 `virtualCamera` 指定。

**注意：** 插件启动的虚拟摄像头在空闲约 60 秒后会停止；你自己在 OBS 里启动的，插件不会关。OBS 场景截图是通过虚拟摄像头取的，所以「OBS 里能看见但插件黑屏」通常是虚拟摄像头没起来。

#### 2.4.2 VTube Studio（形象 / 透明层）

**必须补的设置：**

1. VTS 设置 → API → 开启，端口 **8001**（插件默认）。
2. 加载模型。
3. 第一次连接时，在 VTS 弹窗里允许 Seirein；授权 token 会存到 `<数据根>\vts-token.json`。
4. 想让形象浮在桌面上：VTS 背景设为透明（透明推流）；插件会把 VTS 窗口镜像出来并抠掉背景。
5. 在 Seirein 的 **形象** 卡片点 **连接 VTS**，再点 **测试连接**。

**端口不是 8001：** 插件配置 `vtsPort`（默认 `8001`）；设置页没有输入框。改完重装/重启。

**口型/动作不动：**

- 先确认「已连接」且模型已加载。
- 再看「可注入 / 已验证」：只有 VTS 里真实存在并映射过的参数才会动；名字像但没映射的会被跳过。
- 表情按钮只列出模型真实有的表情；没有就说明模型没配。

**透明层失败：** 确认 VTS 没被最小化、背景透明已开；如果 VTS 窗口不可见，PrintWindow 抓不到画面。可以让插件把 VTS 调出来（编辑模式），再完成编辑。

#### 2.4.3 VB-Audio Virtual Cable（环境声音）

**必须补的设置：**

1. 安装 VB-Cable，重启电脑。
2. 在 Windows 声音设置里确认出现 `CABLE Input`（播放）和 `CABLE Output`（录音）。
3. 回到 Seirein → **环境声音** 卡片；如果组件开关里「环境声音」是关的，点 **开始采集** 会先启用它。
4. 「回环设备」选 `CABLE Output`（如果没有，点刷新/重开设置页）。
5. 点 **开始采集**。
6. 播放一段电脑声音，看状态里是否出现识别文字。

**如果想让 OBS 的声音也进来：** 在 OBS 里把「监视设备」设为 `CABLE Input`。

**「开机自动采集」：** 默认关闭；打开只是授权，不会在打开组件时立刻开始采集。

**没设置会怎样：** 没有可用回环设备时，环境声音启动失败；如果你有「立体声混音」，也可以直接选它。

**重要：** 环境声音只作为上下文，**不会触发回复**；它和麦克风是两条通道。

#### 2.4.4 GPT-SoVITS（本地音色）

**必须补的设置：**

1. 按官方说明装好 GPT-SoVITS，能启动 `api_v2.py`。
2. 确认 API 地址，默认 `http://127.0.0.1:9880`。
3. 准备一段 **3–10 秒** 的参考音频，以及音频里说的那句话（参考文本）。
4. 在 Seirein → 语音合成：
   - 打开「使用 GPT-SoVITS 音色」。
   - 填 API 地址、参考音频路径、参考文本。
   - 选输出语种（text_lang）和参考语种（prompt_lang）。
5. 如果用自己的权重：填 GPT 模型 / SoVITS 模型路径，再点 **应用模型**，仍然需要参考音频。
6. 说一句测试。

**可以在「连带启动」里让插件拉起 GPT-SoVITS：** 填 Python 路径、`api_v2.py` 路径、工作目录和端口，打开自启动。插件启动时尝试一次；已经在运行就跳过。

**没设置 / 失败会怎样：**

- 不填参考音频就打开 GPT：插件会跳过 GPT，直接用 Edge（不会盲目请求一个会返回 400 的服务）。
- 参考音频短于 3 秒或长于 10 秒：同样跳过并回退 Edge。
- 服务超时：回退 Edge；首次冷启动可能很慢。

#### 2.4.5 声纹（CAM++，默认关）

**在哪里：** 设置页 → 听觉 → **声纹影子（只记录，不参与投递）**。

**怎么开：**

1. 点开关，变成「已开启」。
2. 第一次开启会自动下载 CAM++ 模型到 `<数据根>\models\`（约 27 MB；仅默认模型目录会自动下，自定义目录要自己放）；状态会显示「模型下载中」，完成后「模型就绪」。
3. 想登记自己的声音，用设置页里单独的 **声纹** 卡片（在听觉卡片下面）→ **登记我的声纹**：按提示录 3–5 秒，确认后入库。

**代价 / 限制：**

- 只对**麦克风**生效；回环（电脑播放的声音）不跑声纹。
- 只记录判定，不拦截、不改写、不进记忆、不影响投递。
- 多一次 CPU 推理；模型下载需要网络。
- 声纹库为空时显示「无声纹」，不是错误。

**没开会怎样：** 完全不影响听说和记忆；只是没有「这个人像不像你」的记录。

#### 2.4.6 闲聊模式 fastpath（默认关）

**在哪里：** 设置页 → **闲聊模式（可选）** 卡片。

**它是什么：** 原本是用于处理某些对模型性能要求较低的转写子任务，绕过 agent 直接把语音接到闲聊模型；不调用工具、不看屏幕、不查长期记忆，只能简单聊天。

**怎么开：** 点 **开启闲聊模式** → 确认「开启后她只会聊天……」的提示 → 确认开启。

**怎么关：** 点 **关闭闲聊模式**。

**什么时候用：** 只想纯聊天、明确不需要它做事的时候。需要查资料、看屏幕、用工具时，先关掉。

**风险：**

- 开启后它**不会做事**，只会聊天；容易让人误以为「插件变笨了」。
- 语音会直接进闲聊通道，不进入 agent 的工具循环。
- 对话历史单独保存，可以在卡片里 **审阅对话** 或按域清空。

**没开会怎样：** 默认走 agent，功能完整；这是推荐状态。

### 2.5 注意事项

1. **隐私锁只管视觉，不是「全体静音」。**
   开启隐私后：桌面和 OBS 两种采集都停、正在进行的截图取消、助手的所有截图/故事板/切场景请求被拒绝（`/assistant/shot` 返回 403）。它**不切换 OBS 场景，也不关麦克风**。进入后只有用户能用 `Ctrl+Alt+V` 或设置页按钮退出；助手不能自己退出。

2. **回声与设备串音。**
   麦克风下拉会拒绝「立体声混音 / CABLE Output」等回环设备；环境声音则必须用回环设备。开着音箱时，助手自己的声音可能被麦克风收回去。建议戴耳机；不要把回环设备选成麦克风。

3. **候音与打断。**
   你说完一句、助手还没出声时，默认等 **3000 ms** 会说一句简短等待语；正文音频一就绪，等待语会被取消。打断默认只接受**通过校验的成句终稿**；识别中的半成品片段（partial）、咳嗽、回声不会停播。`voice.bargeInPartial` 默认关，就是为了避免误打断。

4. **忙时会拒投递。**
   上一条还在处理时，再说一句不会被排队，而是听到「上一条还在处理，等处理完请再说一次。」等它处理完再说即可。这是故意的，避免把上一轮的回答当成这一轮的。

5. **重载/更新会中断语音。**
   卸载、重装、更新插件会拆掉采集、播放、字幕、形象进程；正在说的话不会跨重载续播。已存在的语音会话如果压缩 preset 没装配，需要重启 DSH，或在没有 live agent 时用 `voice.session.recover`（见 2.6.14）。

6. **上下文有上限。**
   语音会话挂的是 `seirein-voice` 压缩 preset；接近窗口 **80%** 会提示接近上限。压缩不可用时是「降级」而不是「已压缩」；压缩本身不会自动开新会话。上下文特别长时，回答可能变慢或丢细节，这是模型窗口的限制，不是插件能突破的。

7. **数据目录与备份。**
   重要文件都在 `<数据根>`：`memory\memory.db`、`memory\persona.md`、`memory\user.md`、`memory\profile.db`、`memory\speaker.db`、`data\settings.json`、`data\features.json`、`data\events.jsonl`、`vts-token.json`。`cache\` 是临时文件，可以删。
   **备份方法：先退出 DSH，再整个复制 `<数据根>`**。不要在 DSH 运行时复制 SQLite 文件，可能得到不一致的副本。换机器时，把整个数据根复制到新机器，安装插件后把「存放位置」选到同一层父目录，让数据根路径对应上。

8. **单实例与端口。**
   插件没有自己的固定端口，它复用 DSH 的 Web 服务；DSH 的 GUI 端口每次重启可能变化，不要写死。VTS 默认 8001、OBS 默认 4455、GPT-SoVITS 默认 9880；冲突时改上游软件，并同步改插件配置。**同一个数据根只建议给一个 DSH 使用**：目前没有看到跨进程锁，两个 DSH 同时写同一个记忆/事件文件可能互相干扰（`TODO(确认)`）。

9. **GPU / CPU / 内存。**
   语音识别默认跑 **CPU**（流式模型很轻，精识别更吃 CPU，线程数按核心数自动分配）。Edge TTS 不占 GPU，但要网络。GPT-SoVITS 本地推理约占 3–4 GB 显存；OBS、VTS 也会用 GPU。核心数少于 6 的机器会被判为「低配档」，此时环境声音（双路识别）会被拒绝启动，避免拖慢主对话。

10. **TTS 是单槽队列。**
    自动回答、`assistant_say`、候音、打字回合共享一个合成/播放队列；同一时刻不会双播，后到的要排队。GPT-SoVITS 第一次启用或换模型有冷启动，别把它当成故障。

11. **网络依赖。**
    安装依赖、Edge TTS、首次下载 VAD/声纹模型都需要网络。Edge TTS 会把要朗读的文字发到微软的在线语音服务；助手回答由 DSH 配置的模型生成，可能走云端。介意的话，可以关掉语音播报或改用本地 GPT-SoVITS，并自行评估 DSH 模型的隐私设置。

12. **不要手改数据文件来「调设置」。**
    设置页写入的 `settings.json` / `features.json` 有固定结构；手工改容易和界面状态不一致。组件开关只在设置页改；`cordis.patch.yml` 的键改完要重装/重启。

### 2.6 可能遇到的问题（FAQ）

每条都按「现象 → 原因 → 操作」写。先做第 1 步确认，再往下排查。

#### 2.6.1 装完看不到 Seirein

**现象：** 插件页没有 Seirein，或设置页里没有 Seirein 分区。

**原因（按常见程度）：**

1. 安装其实失败了（最常见是被依赖脚本拦下，见 2.6.2）。
2. 装上了但没启用。
3. 首次安装后没重启 DSH。
4. 页面缓存，显示的是旧界面。
5. 系统不是 Windows，或 DSH 版本太旧。

**操作：**

1. 回到 **插件** 页，看有没有失败记录或「安装失败」提示。
2. 有 `ERR_PNPM_IGNORED_BUILDS`：按 2.6.2 允许脚本后重试。
3. 列表里有 Seirein 但显示「已禁用」：点启用。
4. 重启 DSH（不是只刷新页面）。
5. 重启后仍看不到：刷新页面（`Ctrl+R`），再重启一次。
6. 检查 `<数据根>\data\status.json` 是否存在；存在说明 Host 至少加载过一次。
7. 还不行：插件页卸载 Seirein → 重新安装 → 允许脚本 → 启用 → 重启。
8. 确认是 Windows 10/11 x64；非 Windows 不支持语音/视觉/字幕。

#### 2.6.2 安装被依赖脚本拦截（koffi / msedge-tts）

**现象：** 安装最后报错：

```text
[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: koffi@3.1.1, msedge-tts@2.1.1
```

**原因：** pnpm 11 默认不运行依赖的安装脚本；这不是 Seirein 自身要编译，也不是你的环境坏了。

**操作：**

1. 在失败提示里点 **「允许这些脚本并重试」**（Approve builds and retry）。
2. 等安装完成；`koffi` 会使用预编译文件，不需要 C++ 工具链。
3. 如果界面没有这个按钮：先更新 DSH；仍没有就卸载后重新安装，重复第 1 步。
4. 不要选「忽略」；忽略会以退出码 1 结束，插件不会出现。
5. 装好后按 2.1.4 启用并重启。

**开发者 / CLI：** 需要在 profile 的 `pnpm-workspace.yaml` 写入 `allowBuilds:`（`koffi: true`、`msedge-tts: true`）后重试；具体见项目发布检查清单。

#### 2.6.3 没有声音 / 听不到回复

**现象：** 屏幕上有文字或字幕，但听不到助手说话；或者完全没反应。

**先分清：**

- 连文字都没有 → 不是 TTS 问题，先看 2.6.4（麦克风）或模型是否正常。
- 有文字没声音 → 按下面排查 TTS。

**原因：**

1. 「语音合成」组件被关，或「语音播报」被关。
2. 系统输出设备不对 / 音量静音。
3. Edge TTS 需要网络，网络不通或被拦截。
4. 开了 GPT-SoVITS 但服务没启动 / 超时。
5. 上一句还在播，当前句在排队。
6. 没有可用的音频输出设备，WPF 播放失败。

**操作：**

1. 设置页 → **组件开关**，确认「语音合成」是已启用。
2. 设置页 → **语音合成**，确认「语音播报」是已开启。
3. 检查 Windows 音量、输出设备、音量合成器里 DSH 是否被静音。
4. 打开网页测试网络；Edge TTS 需要能访问微软服务。
5. 如果开了 GPT-SoVITS：先关掉「使用 GPT-SoVITS 音色」，让它回退 Edge，确认是不是本地服务的问题。
6. 等上一句播完再试；不要连续快速发问。
7. 仍无声：重启 DSH，再让助手说一句。

#### 2.6.4 麦克风没反应 / 一直「聆听中」

**现象：** 点测试麦克风后状态是「监听中」，但说话不出字；或者一直显示未启动。

**原因：**

1. FFmpeg 没找到（插件不从 PATH 找）。
2. 流式 ASR 模型缺失或目录不对。
3. 选错了输入设备，或设备被其它软件占用。
4. 门限太高，声音被当成静音。
5. 选到了回环设备（会被拒绝）。
6. 「听觉」组件被关，或没有点开始。

**操作：**

1. 看「听觉」卡片的状态和错误文字。
2. 报「未找到 ffmpeg」：把 `ffmpeg.exe` 放到 `<数据根>\bin\ffmpeg.exe`，或设 `DSH_FFMPEG_PATH`，重启。
3. 报 `ASR 模型缺失：<路径>`：按 2.2.5 把 4 个文件放到那个路径。
4. 点「刷新」重新选设备；不要选灰色的回环设备。
5. 关掉其它占用麦克风的软件（会议、录音、直播软件）。
6. 把门限往下调（例如 `-55`），保存，看到「已生效（新实例）」。
7. 重新点 **测试麦克风**，说话看 dB 是否跳动。
8. 仍不行：重启 DSH，再试。

#### 2.6.5 ASR 不识别或乱码

**现象：** 能出字，但字不对、语言不对、重复、像乱码。

**原因：**

1. 语音语种和实际说的语言不一致。
2. 默认流式模型是中文模型，其它语种实时结果会更差。
3. 精识别模型没放或目录不对，终稿没有修正。
4. 麦克风太远、噪声大、回声重。
5. 门限太低，把环境噪声也当成说话。

**操作：**

1. 设置页 → 语种，把「语音语种」改成你实际说的语言。
2. 按 2.2.6 放好 SenseVoice 精识别模型，确认目录里是 `model.int8.onnx` + `tokens.txt`。
3. 确认流式模型目录里是完整的 4 个文件，没有多套一层文件夹。
4. 麦克风靠近一点，戴耳机减少回声。
5. 把门限往上调一点（例如 `-45`），减少噪声触发。
6. 换一个麦克风或 USB 接口再试。
7. 日语 / 韩语 / 粤语仍很差：默认流式模型主要针对中文；换语种需要换流式模型目录（高级配置 `asrModelDir`）。代码接受任意 sherpa-onnx streaming zipformer transducer 目录（含 `encoder/decoder/joiner` 的 `.onnx` 与 `tokens`）；具体语种型号未逐一验证，先把官方对应语种模型按同样结构放进去再试。

#### 2.6.6 字幕不显示

**现象：** 助手说话了，但屏幕上没有字幕。

**原因：**

1. 字幕组件关了，或字幕本身没启用。
2. 区域模式没有选区域。
3. 气泡模式没有开启桌面悬浮（没有可依附的窗口）。
4. 字幕被其它全屏窗口盖住，或在另一块屏幕。
5. WPF/PowerShell 叠加层没起来。

**操作：**

1. 设置页 → **组件开关**，确认「字幕显示」已启用。
2. 设置页 → **字幕**：
   - 点 **启用字幕**。
   - 区域模式：点 **选择区域**，在屏幕上拖一个框，看到坐标后保存。
   - 气泡模式：先在形象卡片开启 **桌面悬浮**，再切气泡模式。
3. 点 **预览**，看是否有测试字幕。
4. 确认没有全屏游戏/视频盖住；把字幕区域放到主屏。
5. 仍不显示：关掉字幕再启用，或重启 DSH。

**注意：** 代码里字幕的显示开关默认是**关**的；「字幕显示」组件默认开，但第一次仍需要你点「启用字幕」并选区域/开悬浮。

#### 2.6.7 VTS 连不上 / Live2D 不动

**现象：** 形象卡片显示「未连接」或「WebSocket 已打开，但认证未完成」；或连上了但模型不动。

**原因：**

1. VTS 没开，或没开 API。
2. 端口不是 8001。
3. 授权弹窗没点允许，或超时。
4. token 失效。
5. 模型没有对应参数/热键/表情，或没有映射。
6. VTS 窗口被最小化，透明层抓不到。

**操作：**

1. 打开 VTS，加载模型，确认 API 已开启、端口 8001。
2. 回到形象卡片点 **连接 VTS**；在 VTS 弹窗里点允许（60 秒内）。
3. 状态显示「已连接」后点 **测试连接**。
4. 仍失败：点「连接 VTS」（已连接时按钮显示「重新连接」）；还失败就重启 VTS 和 DSH。
5. 连上了但不动：看「可注入 / 已验证」；只有 VTS 里真实存在并映射过的参数才会动。没有映射的会被跳过，这是正常行为。
6. 透明层不显示：确认 VTS 没最小化、背景透明已开；用「编辑模式」把 VTS 调出来再完成编辑。
7. 端口不是 8001：改 VTS 或插件配置 `vtsPort`，重装/重启。

#### 2.6.8 OBS 找不到 / 虚拟摄像头失败

**现象：** 视觉与隐私里刷新不出场景；或选了场景但截图黑屏；或报「未找到 OBS Studio」「虚拟摄像头」相关错误。

**原因：**

1. OBS 没装，或装在非默认位置。
2. OBS 没开，或 WebSocket 没开。
3. 端口/密码不匹配。
4. 虚拟摄像头没启动，或设备名不是 `OBS Virtual Camera`。
5. OBS 场景本身是空的/黑屏。
6. FFmpeg 没找到（场景模式也需要 ffmpeg 读虚拟摄像头）。

**操作：**

1. 打开 OBS，确认版本 30+。
2. 工具 → WebSocket 服务器设置：端口 4455，建议关闭认证。
3. 启动 OBS 虚拟摄像头；在 Windows 相机应用里确认能看到 OBS 画面。
4. 设置页 → 视觉与隐私 → **刷新场景**，选场景，点 **截图测试**。
5. 黑屏：换一个有画面的场景；确认虚拟摄像头没被其它软件占用。
6. 报找不到 OBS：把 OBS 装到默认位置，或高级配置 `obsPath` 指向 `obs64.exe`，重启。
7. 报密码：在插件配置里填 `obsPassword`，或关闭 OBS 认证。
8. 确认 FFmpeg 已按 2.2.4 放好。

#### 2.6.9 FFmpeg 找不到

**现象：** 测试麦克风报「未找到 ffmpeg」；截图/故事板失败。

**原因：** 插件只检查固定位置，不扫描系统 `PATH`。

**操作：**

1. 把 `ffmpeg.exe` 放到 **`<数据根>\bin\ffmpeg.exe`**。
2. 最好把 `ffplay.exe` 也放进去（播放更快）。
3. 或者设环境变量 `DSH_FFMPEG_PATH` 指向 `ffmpeg.exe`。
4. 或者高级配置 `ffmpegPath`。
5. 改完重启 DSH。
6. 再点 **测试麦克风** / **截图测试**。

**注意：** 在命令行里能运行 `ffmpeg` 不代表插件能找到；必须放到上面的位置之一。

#### 2.6.10 回声 / 自己听到自己

**现象：** 助手说话时，麦克风把它的声音收回去，导致重复、误打断，或像在自言自语。

**原因：**

1. 用外放音箱，麦克风离音箱太近。
2. 把回环设备选成了麦克风。
3. 门限太低，环境声/回声被当成说话。
4. 开了「响亮片段也能打断」的实验开关（配置名 `voice.bargeInPartial`，默认关），回声也可能打断。

**操作：**

1. 戴耳机，或把麦克风换成靠近嘴的耳麦。
2. 听觉 → 输入设备：不要选「立体声混音」「CABLE Output」等回环设备（它们本来就会灰掉）。
3. 门限往上调（例如 `-40`），减少回声触发。
4. 保持 `voice.bargeInPartial` 关闭（默认就是关）。
5. 环境声音要用回环设备，但它是独立通道，不会触发回复；不要把它的设备当成麦克风。
6. 仍严重：降低音箱音量，或换用指向性麦克风。

#### 2.6.11 上下文超限 / 提示压缩不可用

**现象：** 聊久了变慢、忘事；或状态提示压缩不可用 / 需要恢复会话。

**原因：**

1. 语音会话的上下文接近模型窗口上限（约 80% 会提示）。
2. `seirein-voice` 压缩 preset 没有装配到已存在的会话。
3. 压缩执行了但没释放多少，仍处于高压力。
4. 模型窗口本身有限，插件不能突破。

**操作：**

1. 先按 2.6.14 点 **恢复当前语音会话**（会重新装配压缩 preset 并压缩一次；历史不删除）。
2. 如果提示「需重启 DSH 释放 agent」：重启 DSH，再点一次恢复。
3. 仍提示接近上限：等当天语音会话在凌晨 4 点日切后开新会话，或减少一次性长文。
4. 不要期待「压缩后和没聊过一样」；压缩只是把旧内容变短，细节会损失。
5. 若只是普通对话变慢，先确认不是网络/模型服务问题。

#### 2.6.12 隐私模式开 / 关，以及「agent 不能退出」

**现象：** 助手说它不能退出隐私；或你想关掉隐私但找不到入口。

**原因：** 隐私是**用户侧采集锁**，规则是「助手可以进入，只有用户能退出」。

**操作：**

1. 按 `Ctrl+Alt+V`（默认热键），或打开设置页 → 视觉与隐私 → 点 **退出隐私模式**。
2. 如果改过热键：设置页 → 全局快捷键，看当前 `vision` 绑的是什么。
3. 如果热键冲突：直接用设置页按钮，它不依赖热键。
4. 助手请求退出隐私是**正常被拒绝**的；这是设计，不是 bug。只有你能解锁。
5. 隐私锁不关麦克风；想静音请用麦克风热键或听觉卡片停止采集。
6. 隐私期间截图接口返回 403；退出后重新截图/观看即可。

#### 2.6.13 设置页保存后没生效（需重启 / 刷新）

**现象：** 改了设置，界面显示成功，但行为没变。

**原因：**

1. 改的是「存放位置」，必须重启 DSH。
2. 改的是插件配置文件（高级），必须重装/重启。
3. 改的是需要重新连接的设备/服务（麦克风、VTS、OBS）。
4. 页面是旧缓存。
5. 改的是「下一轮才生效」的选项（例如候音等待）。

**操作：**

1. 存放位置：重启 DSH。
2. 插件配置：卸载 → 重装 → 启用 → 重启。
3. 麦克风：点 **测试麦克风** 重新开始采集；门限保存后会自动重启采集，看到「已生效（新实例）」。
4. VTS：点 **重新连接**。
5. OBS：点 **刷新场景**，必要时重启 OBS 虚拟摄像头。
6. 字幕：点 **预览**；不行就关掉再启用。
7. 页面旧：`Ctrl+R` 刷新；还旧就重启 DSH。
8. 仍不对：看设置页顶部的版本号是否为 v0.99.0；不是就重新安装。

#### 2.6.14 恢复旧会话（voice.session.recover）怎么用

**现象：** 聊久了提示上下文接近上限 / 压缩不可用；或设置页提示需要恢复语音会话。

**原因：** 已经存在的语音会话没有装配压缩能力，或原来装配的会话需要手动重建一次。

**它解决什么：** 给已存在的语音会话重新挂上 `seirein-voice` 压缩能力，避免上下文压力一直升高。

**在哪里：** 设置页靠上的 **「恢复语音会话（诊断）」** 卡片（在诊断/时间线附近）。

**操作：**

1. 先确认没有正在进行的语音回合；最好也没有其它 agent 正在使用这个会话。
2. 点 **恢复当前语音会话**。
3. 看到确认提示后，点 **确认恢复**。
4. 等结果：成功会显示已恢复/已压缩；失败会显示原因。
5. 成功后继续对话即可；历史不会被删除。

**它实际做什么：** 保留同一个会话 id，重新挂上 `seirein-voice` 压缩 preset，并先压缩一次；不会自动调用、不会轮询、不会新建会话、不会删除历史。

**常见失败：**

- 「需重启 DSH 释放 agent 后再恢复」：说明还有正在运行的助手会话占着它；重启 DSH 后再点。
- 恢复后仍提示接近上限：压缩释放得不够；可以等日切新会话，或减少长文。
- 找不到这个卡片：先确认设置页加载的是 v0.99.0；旧版本没有这个入口。

**更早的日期：** 设置页按钮恢复的是**当天**的语音会话（`seirein-YYYY-MM-DD`，凌晨 4 点日切）。要恢复更早的会话，需要调 `voice.session.recover` 并带 `sessionId`，属于开发者操作。

**2.6.15 实在是有些步骤不会怎么办**

**最简单的解决方案：学会依靠助手的力量，设置（应该）全部向助手开放修改权限。如果你有不会的，发语音或者文字问她，甚至直接让她处理，成功的概率可能比你自己胡乱尝试更高。**

## 3. 项目设计与实现思路

### 3.1 总体框架

Seirein 是 DSH 的 **bundle 插件**：`cordis.patch.yml` 在加载期插入一行 `dsh-assistant`，插件入口 `src/host/index.js` 在 Host（Node 模式子进程）里装配服务、工具、事件与 HTTP；设置页 `client.js` 跑在浏览器里，通过 DSH 的 Web 服务与 Host 通信。两者不共享进程，也不互相 import。

```text
DSH Host（Node 模式子进程）
└─ @local/dsh-assistant（src/host/index.js，唯一入口）
   ├─ cordis.patch.yml  → 插入 dsh-assistant 插件行（id / name / config 默认值）
   ├─ FeatureStore      → data/features.json（8 个组件开关，带启停钩子）
   ├─ 服务层            → hearing / speech / memory / vision / avatar / subtitle / session / profile / platform
   ├─ 工具面            → ctx.tools.register × 24（定义在 index.js，execute 在 runtime/tools.js）
   ├─ 事件接缝          → session/event、agent/pre-step、tools/execute；agent/created 由压缩模块订阅
   ├─ HTTP              → /assistant/status、/assistant/action、/assistant/shot
   ├─ 客户端            → client.js（package.json 的 dsh.client → settings.plugins.tab + settings.section）
   └─ 外部进程 / 服务    → ffmpeg / ffplay、PowerShell + WPF、VTS WebSocket、OBS WebSocket、GPT-SoVITS HTTP、Edge TTS
```

| 接入面 | 实现方式 | 说明 |
| --- | --- | --- |
| 插件装载 | `cordis.patch.yml` 的 `insert` | 一行 `dsh-assistant` 与默认 config；组件开关不在这里 |
| 工具注册 | `ctx.tools.register` | 名称 / description / parameters / schema / render 在 `index.js`，execute 在 `runtime/tools.js` |
| 会话事件 | `ctx.on('session/event', …)` | 观察回答、工具、turn、stream，驱动语音、记忆与动作；不修改宿主事件 |
| 请求前上下文 | `ctx.on('agent/pre-step', …)` | 记忆注入、日切摘要、视觉预取、识别残片提示；只追加，不改宿主的决定 |
| Agent 生命周期 | `ctx.on('agent/created', …)` | 由 `session/compaction/voice-compaction.js` 订阅：给当天语音会话挂压缩 preset |
| 工具执行 | `ctx.on('tools/execute', …)` | 只给宿主的 `session_search` 加一层超时预算，不改工具语义 |
| HTTP | `ctx.inject(['webServer'], …)` + `webServer.register({ kind: 'exact' })` | 状态、动作、截图缓存三个端点，路径精确匹配 |
| 客户端 | `package.json` 的 `dsh.client` + `ctx.slots` | `client.js` 注册 `settings.plugins.tab` 与 `settings.section`，面板通过 HTTP 读写 |
| 组件开关 | `FeatureStore` | `data/features.json`；启用 / 关闭有生命周期钩子，不是纯 UI 状态 |
| 生命周期 | `ctx.effect` | 采集、播放、字幕、WebSocket、子进程、计时器都挂在 effect / disposer 上 |
| 外部服务 | 直接 HTTP / WebSocket / 子进程 | 不依赖 Harness 包；失败时降级或报错，不静默 |

这里**没有独立的消息总线**：宿主事件一律用 `ctx.on` 订阅，插件自己的观测写 `data/events.jsonl`（每行 `{id, ts, type, corr_id, payload}`，10 MB × 5 轮转）。代价是所有跨模块通知都得顺着具体订阅点找，读代码时不能假设有一个统一事件中心。

几条结构约定：

- 子目录按职责再分：`session/{compaction,conversation,delivery,events,inference,timeline}`、`runtime/{http,settings,diagnostics}`、`avatar/{presets,spout-layer}`、`hearing/interaction`。
- 发布清单以 `package.json.files` 为准：`client.js`、`src/host/**`、`cordis.patch.yml`、`locale/*.json`、`Seirein.ico`、`Seirein.png`；新增运行资源必须放进这些路径。
- 只有纯文本 / 时间函数进 `shared/`，跨域生命周期进 `runtime/`，不要为了方便 import 把业务模块塞进 `runtime/`。

### 3.3 总体设计思路

下面先给一条完整链路，再按「这套设计要解决什么问题」拆开。只讲已经实现、而且能在代码或测试里核对的做法；未实现或默认关闭的会单独标明。

#### 3.3.1 一次语音交互的主链路

```text
热键 / 设置页开麦
  → 采集：ffmpeg dshow，16 kHz 单声道 PCM
  → 流式识别（partial）+ VAD / 端点
  → 终稿（SenseVoice）+ 噪声 / 低证据影子（默认只记录）
  → 打断判定：播放中只有通过校验的成句 final 才能停播
  → 投递：当天 seirein-YYYY-MM-DD 会话（<root>/workspace）；上一个回合没结束就拒绝，不排队
  → 请求上下文：人设 / 画像 / 固定记忆 / 环境事实（system section）+ 相关记忆 / 连续台词 / 日切摘要（agent/pre-step 追加）
  → 候音：投递后 3000 ms 仍未出声，先说一句等待语；正文音频就绪即让位
  → Agent 循环（工具调用、会话结果）
  → 正文完成 → 口语版决策（短答原样 / 长答一次改写 / 失败回落全文）
  → 语音语言 + 字幕语言两条翻译流
  → TTS 合成（Edge / GPT-SoVITS，分块与预取）→ 单播放席位 → ffplay
  → 字幕叠加 + 口型 / 动作 + 记忆写入
```

并行的旁路：

- **视觉**：只有视觉工具被调用、或本轮话里明确要求看时才取图；普通闲聊不会自动附图。回合内的预取见 3.3.2。
- **动作**：由播放、句间、回答起始等事件驱动，独立于文本与音频，只写当前模型验证过的通道。
- **记忆**：消息边界自动记录（不占热路径）；召回只通过 `agent/pre-step` 注入。
- **压缩**：由语音会话挂载的 preset 在宿主侧触发，不打断正在播放的句子；不可用是可见降级。
- **环境音**：只进上下文，不触发回复，也不占语音投递的所有权。
- **打字回合**：GUI 里打字的回合结束后仍走同一个语音出口与同一本账本。

#### 3.3.2 关键问题与解决方式

**上下文溢出：复用 DSH 原生压缩，不自己滚会话。**

语音会话挂一个只含压缩能力的 `seirein-voice` preset（`compaction-basic` / `command-compact` / `tool-result-pruner` 三行，`compaction` 与 `toolResultPruner` 各自 isolate），由插件在挂载时自己注册——新机器不需要手写 profile patch，也不会打开宿主全局压缩。

同 ID 的 preset 已经存在时先核对内容：只允许压缩行，夹带 `tools` / `persona` / `permissions` 等任何一项都判为 `conflict`，既不覆盖也不挂载。注册失败不是静默的：`status` 给出 `enabled:false` 与原因。压力到窗口的 80% 时置 `near-limit`，并写一条节流过的 `voice.compaction.near-limit`；压缩后仍在 80% 以上、或什么都没释放，只标记 `stillNearLimit` 并给建议。

**边界**：不自动换会话、不自动新建会话、也不反复压缩；已运行的 Agent 需要重启或手动执行 `voice.session.recover`；没有 token meter 时窗口按 128k 估算。

**动态观察注入：按步快照，变化才追加历史。**

变化中的观察（非语言线索、连续台词）不写成 system section，而是通过 `systemPrompt.context` 发布：宿主在**内容变化时**追加一份带来源的用户角色快照（相同内容不重复追加）；旧快照仍留在历史里，等自动压缩回收，所以“过期/清空”只影响当前渲染，不会删除历史消息。非语言线索本身是实验开关，默认关。

隔离是严格的：这些观察只渲染给当天那一个 `seirein-YYYY-MM-DD` 会话；其它会话、子代理、读不到身份的 agent 一律渲染空串。

过期在读取时计算：非语言线索 5 分钟有效、连续台词按时间与字符裁剪，过期或没内容就渲染空，不创建计时器。

渲染有硬上限：连续台词一次最多 3600 字符（给宿主的 3700 字符快照预算留头），超了从最旧处省略并写「已省略 N 字符」；再按层配额收一次（`ephemeral` / `recent`）。

环境事实是单独的 section `assistant:environment`（排在人设之后）：带来源与观察时间，所有会话共享，不随步骤变化。

**边界**：快照每一步都会重放，模型侧仍要读；观察是尽力而为，音频事件没产生就没有对应的 cue。

**回答重复、复述正文：按需求组织的口语版。**

口语版不是「把正文压短」，而是一次按需求重新组织：所有入口共用同一条指令（`SPOKEN_VERSION_GUIDE`），在同一次改写请求里完成五步——识别本次需求 → 选取要说的信息 → 保留所选结论的必要条件 → 按人设重新组织口头表达 → 检查清晰度与冗余。不做额外的分析调用。

必须保留的是会改变结论的内容：否定、适用条件、关键数字、时间、风险与不确定性；用户一次问了多个问题就逐项回应。

长度是结果不是目标：没有固定压缩比，字数只是软性的防铺陈约束；用户本轮明确要求详细、完整列举或全部朗读时，按正文完整度表达。

短答（≤60 字且 ≤2 句）直接原样播；长答最多一次轻量改写；改写失败回落完整正文，不截断成摘要。

**边界**：只改写一次，不会为了更短再跑一轮；模型不遵守时仍有输出形状的硬约束（一段口语、无标题与列表符号）。

**回声与误识别：只在高置信时丢。**

真正会丢输入的噪声规则只有高置信回放回声：必须在播放、必须和「真正送进 TTS 的语音文本」连续匹配、去掉标点后整句仍等于回声、且没有任何额外内容。多出任何一个字（否定、纠正、停止指令）都会让它通过，不会剪掉用户的话。填充词与同一句的重复投递也会被拒，但那是去重，不是噪声判定。

参考文本只取语音语言那一版，不拿另一语种的字幕比对——那只会制造假回声。

低证据（播放中的短文本、VAD 比例过低、离线静音幻觉）只计算 `wouldDrop` 并写影子，默认不拦截投递；`voice.lowEvidenceGate` 打开后才真正生效。

声纹（CAM++）同样只是影子：登记、打分、`match/unsure/no-match`，不参与路由，也不参与投递决策。

**边界**：静音幻觉默认仍会投递；声纹阈值没按本机校准，不能当「只认主人」用。

**动作生硬：预设库、单写者、起始接替。**

动作来自只读预设库：`recipes.js` 写符号编舞与 `requires`，`catalog.js` 展开成稳定 ID 的节奏变体。选择器只做硬过滤（状态、事件、语义、能力、禁用、隐私）和打分，输出候选，不直接写参数。

只有一个参数写者：`avatarRuntime` 拥有连接代次与已验证通道，控制器在同一帧里复核通道占用、旧代次、速度 / 加速度与最终优先级；预设不携带模型参数名。

回答起始接替：回答第一块音频真正开始时，还停着的思考 / 倾听类预设可以在短窗口内被接替（通道集合必须可拆分）；接不了就丢弃这个开场动作（`takeover-unavailable`），而不是拖到 `speechEnd` 再补一个过时的动作。

通道不退化：只用当前模型验证过的语义通道；未映射 / 未验证的通道在状态与设置页明确标注（`unmapped` / `unverified`），不假装可用，也不降级成热键。

**边界**：能力过滤会让可用动作变少；身体与呼吸不归预设执行器写（保留 VTS 自己的动画所有权），需要这两个通道的条目会被直接过滤。

**事件日志被刷屏：源侧聚合、读取侧白名单。**

日志在源侧聚合：同类事件不逐条写，而是按窗口合并——端点静音每 10 条留 1 条、被跳过的投递折叠成一条 `asr.delivery.order.summary`、外部会话的跳过按窗口合成一行；窗口由下一条同类事件或会话结束惰性冲刷，不为日志建计时器。

读取侧是白名单：诊断只认固定探针，逐字段投影（`voice.latency`、`noise.shadow`、`turn.timeline`、`pipeline.timeline`、`hotkeys`、`memory.stats`、`spout`），不返回原始事件行，也会剥离凭据形状的字符串。

保留窗口靠轮转：10 MB × 5 代，够排查最近一段时间，但不是审计日志。

**边界**：诊断默认关闭，需要在 `settings.json` 打开 `diagnostics.enabled`（或 config `diagnosticsEnabled`）；被轮转掉的旧记录找不回来。

**延迟说不清：单轮时间线加席位归因。**

每一轮写一条 `voice.turn.timeline`：把 `turn/start`、`step/start`、`assistant/message`、`tool/call`、`tool/result`、`turn/end` 归约成模型轮次、工具区间并集、首字 / 首音边界与残差（`residualMs = 总时长 - 各阶段`）。工具并集不把并行调用相加，另给 `toolMsSum`；观测不到的值写 `null`，不写 0。

首音之前拆成四段独立时钟：翻译、合成、席位 / 排队等待、真正出声；`speech.seat.wait` 记录等待时长、队列深度与所属会话 / 回合，用来区分「模型慢」还是「没轮到播」。

诊断探针 `turn.timeline` 与 `pipeline.timeline` 只读，默认不返回阶段数组，需要时再显式带上限展开。

**边界**：残差可能为负（它是信息，不是错误）；时间线是单轮的，不跨轮串联。

**上下文预算：分层配额，受保护层不裁。**

提示词按五层记账：`persona`、`fixed`、`memory`、`recent`、`ephemeral`。`persona` 与 `fixed` 受保护，永远整段渲染；只裁后三层，而且按整条 / 整行裁剪，不切断半条记录。

三个入口各自配额：语音会话（`voice`）、打字会话（`typed`）、闲聊快路（`fastpath`）；快路保留原来的 6000 字符总包络。默认值刻意宽松，只用来兜住病态长度，可以用 config 的 `contextBudgets` 收窄。

每层丢了多少都单独计数，报告里只有数字与层名，不带正文。

**边界**：默认配额不是「省 token」策略；总配额压得很小时，persona + fixed 仍然完整。

**视觉预取：同一回合只采一次。**

`agent/pre-step` 每一步都会为该回合开一个视觉作用域；只有用户本轮的话确实在要求看（关键词判定）时，才会在第一次模型请求之前预取一次。

同一回合里的所有视觉读取（`assistant_see`、`assistant_watch take`）先问这个通道：同回合、同来源 / 场景、30 秒内才复用；来源或场景变了、回合变了、隐私锁了，都是 miss。

迟到的结果按 `(sessionId, turn, epoch)` 认领：新回合开始后旧采集落地会被丢弃（`vision.pre-request.stale`），不会覆盖新回合的帧；失败也只清自己的条目。

单帧和故事板是两种产物：`assistant_see` 要单帧，`assistant_watch` 要打包的时间序列，类型不同就算 miss，不能互相冒充。

**边界**：这是优化，失败 fail-open；关键词判定偏窄，漏判时退回工具采集，多一次工具往返。

**会话恢复：重装配再压缩。**

`voice.session.recover` 是唯一能手动重建已存在语音会话的动作：保留同一个 session id，通过 `agentLoop.resume` 在 setup 里重新挂上压缩 preset，再调用一次 preset 自己的 `compactNow()` 后返回。

它不新开会话、不写用户消息、不删历史、不排程、不轮询；失败原样报告，不重试。

只接受 `seirein-YYYY-MM-DD` 形态的会话；还有活着的 Agent 占着它时拒绝，并提示先重启 DSH。

**边界**：恢复后如果压力仍在 80% 以上，只给「新会话 / 手动压缩」的建议，不会替你执行。

#### 3.3.3 取舍与边界

| 取舍 | 做法 | 原因 | 代价 |
| --- | --- | --- | --- |
| 统一语音出口 | 自动回答、`assistant_say`、候音、打字播报都走同一本播放账本与一个播放席位 | 避免双播、抢麦、字幕与口型错位 | 所有播报串行，长队列要等 |
| 忙时拒投递 | 上一个回合没结束时拒绝新语音，并说明「上一条还在处理」 | 排队会把旧请求的答案说成新请求的 | 用户需要再说一次 |
| 上下文观察走快照 | 非语言线索 / 连续台词走 `systemPrompt.context`（内容变化才追加）；环境事实走独立 section；人设 / 画像 / 固定记忆走 section | 观察不会每步改写系统提示；最新快照在上下文中生效 | 旧快照仍留在历史，等自动压缩回收；渲染侧只展示当前有效内容 |
| 记忆只在 `agent/pre-step` 注入 | 用户原话原样投递，记忆作为额外上下文追加 | 避免「拼在用户消息里」导致原话被改写、重复召回 | 注入时机受宿主 pre-step 预算约束 |
| 压缩 preset 随插件走 | 插件注册 `seirein-voice`（只含压缩三件套），挂到当天语音会话 | 新机器不需要手写 profile patch；不打开宿主全局压缩 | 冲突 / 未装配时降级；需重启或恢复 |
| 动作单一写者 | `avatarRuntime` 是唯一参数写者，预设只给候选 | 防止两个循环抢同一参数、抖动、旧代次复活 | 预设要过能力过滤，可用动作变少 |
| 隐私只锁视觉 | `privacy` 停采集、拒截图、取消在途，不动麦克风、不切 OBS | 用户要的是「别看我」，不是「别听我」；OBS 场景由用户控制 | 语音仍在工作，需要自己静音 |
| Windows 专属实现 | 麦克风 / DPAPI / WPF / 字体 / 窗口几何都直接依赖 Windows 能力 | 这些能力在 Host 的 Node 子进程里没有 Electron 等价物 | 非 Windows 环境语音、视觉、字幕不可用 |
| 未观测写 `null` | 延迟字段、记忆命中、首音声道等没测到就是 `null` | 不把缺失当 0，避免统计被拉低 | 报表要处理空值 |
| 失败不静默 | GPT-SoVITS 失败回落 Edge；压缩失败报 `enabled:false + reason`；黑帧拒绝交付 | 宁可降级也要可见 | 状态更复杂，需要读原因 |
| 不自动滚动会话 | 压缩只告警与建议，恢复只接受显式动作 | 换会话、删历史都是不可逆决定，应由用户做 | 长会话需要用户自己处理 |

### 4.2 目录与模块约定

- **`src/host/index.js` 只做装配**：创建服务、注册工具 / 事件 / HTTP、跨域接线、生命周期。业务逻辑放功能目录；`test/module-layout.mjs` 会断言 host 根只有一个入口。
- **领域模块不反向 import 入口**：功能模块不得 `import '../index.js'`；依赖通过参数或 getter 注入，避免循环依赖。只有同时被两个以上功能域使用的纯文本 / 时间函数才放 `shared/`。
- **领域模块尽量纯**：解析、计算、状态机不直接启动设备、进程或模型；有外部副作用的服务由宿主创建并通过参数注入，模块导入本身不产生副作用。
- **跨域生命周期放 `runtime/`**：依赖引用计数、关闭顺序、HTTP、诊断。不要为「方便 import」把业务模块塞进 `runtime/`。
- **presets 只读**：`avatar/presets/` 是版本控制的数据与查询模块；用户覆盖写 `data/motion-presets.json`，不写回源码。预设不携带模型参数名，不创建第二套参数写者。
- **`test/` 必须上传**：测试是提交的一部分；新增行为要有对应 `test/*.mjs`，真机脚本在文件头标 `// @live` 或加入 `scripts/test-batch.mjs` 的 `LIVE_FILES`。
- **发布清单**：`package.json.files` 是 `client.js`、`src/host/**`、`cordis.patch.yml`、`locale/*.json`、`Seirein.ico`、`Seirein.png`；`exports` 暴露入口、`client`、`locale` 与 `icon`。新增运行资源要放进这些路径，不能只留在仓库根。
- **客户端入口固定在根 `client.js`**；`CLIENT_VERSION` 与 `package.json.version` / `PLUGIN_VERSION` 一起升。
- **不要用 PowerShell 写源码**（BOM / 乱码）。

### 4.3 开发流程

#### 加一个工具

1. 在 `src/host/index.js` 的工具定义区加 `name` / `description` / `parameters` / `outputSchema` 与 `render`。
2. 在 `src/host/runtime/tools.js` 加 execute 实现（参数解析、调用服务、返回结构）；工具实现不持有宿主状态。
3. 更新 `test/smoke.mjs` 的工具数量断言（当前 24）与相关 schema 测试。
4. 如果工具有跨域副作用，补一条定向测试（参考 `test/tool-content.mjs`、`test/tool-schema-vision.mjs`）。

#### 加一个模块

1. 按功能域落位（`hearing/`、`speech/`、`memory/` 等）；只有纯文本 / 时间函数进 `shared/`，跨域生命周期进 `runtime/`。
2. 模块只接收显式依赖，不 import `index.js`；导入本身不启动设备 / 进程 / 模型。
3. 如果需要对外暴露，在 `index.js` 里 re-export（保持原入口导出面）；不需要就只做内部导入。
4. 在 `test/` 加同前缀测试；跑 `node --test test/module-layout.mjs` 确认资源与导入路径可解析。

#### 加一个动作预设

1. 在 `avatar/presets/recipes.js` 增加 `recipe`：`operations` 只写符号编舞，`requires` 只写当前运行时验证过的语义通道。
2. `catalog.js` 会按 recipe × 4 种节奏展开变体；稳定 ID 用 `recipe.variant`，不要依赖显示名。
3. 只使用已声明通道（头 / 眼 / 眉 / 身体 / 呼吸）；没有验证输入的部位不要假装可用，也不要把动作降级成热键。
4. 设置页的启用 / 禁用 / 优先级通过 `motion.presets.*` 写入 `data/motion-presets.json`；不要改源码数据。
5. 跑 `test/motion-preset-library.mjs`、`test/preset-execution.mjs`、`test/motion-presets-native-unmapped.mjs`。

#### 加一个设置页项

1. 在对应功能的 `settings-actions.js` 的 `ACTIONS` 里加动作名，并实现 handler；重复动作名会在 `createSettingsRouter` 里直接抛错。
2. 需要新持久化字段时写入 `<root>/data/settings.json`（运行设置）或 `features.json`（组件开关），不要混用。
3. 在 `client.js` 加卡片 / 行，用 `act({ action, ... })` 调 `/assistant/action`；状态从 `/assistant/status` 读。
4. 补动作测试（参考 `test/hearing-ui.mjs`、`test/tts-ui.mjs`、`test/profile-ui.mjs`）。

#### 加一个组件开关

1. 在 `runtime/features.js` 的 `DEFAULT_FEATURES` 注册 `{ id, label, description, default }`。
2. 需要启停资源时提供 `onEnable` / `onDisable` 钩子；状态持久化到 `features.json`。
3. 组件关闭必须真正停止采集 / 播放 / 子进程，不能只改 UI。

#### 测试与基线

- 定向：`node --test test/<file>.mjs`。
- 全量：`node scripts/test-batch.mjs`（按前缀分批、批间 2000 ms、失败不阻断；EBUSY / ENOTEMPTY / EPERM 自动重跑一次，flaky 单独计数）。
- 真机：`--include-live`；默认排除 `spout-layer`、`spout-dispose`、`facefound-live`、`reasoning-off-live` 与 `*-live.mjs`。
- 基线：`node scripts/baseline-snapshot.mjs` 产出 `<root>/cache/baseline-<时间戳>.json` 与 `.md`；`--compare` 在可比较投影变化时退出码为 1。
- 发布前：`npm pack --dry-run --json` 检查 `files` 清单，确认 worker、PowerShell、Spout 资源都在包里。

### 4.4 已知限制与待办方向

以下条目是已知限制与待办方向；标着「未实现 / 未启用」的，不要当成已完成的功能。

| 项 | 现状 | 影响 / 方向 |
| --- | --- | --- |
| P-46 逐轮时间线 | 已实现：每轮一条 `voice.turn.timeline`（模型轮次、工具区间并集、首字 / 首音边界、残差 `residualMs`），并作为附加字段并入 `voice.latency`；诊断探针 `turn.timeline` / `pipeline.timeline` 默认不返回阶段数组 | 时间线是单轮的，不跨轮串联 |
| P-48 视觉准备复用请求前通道 | 已实现：`agent/pre-step` 开回合作用域，只有「要看」类请求预取一次；同回合复用受 30 s 与来源 / 场景约束，迟到结果丢弃；单帧与故事板分开 | 是否「要看」由关键词判定，漏判时退回工具采集（多一次工具往返） |
| P-50 关键等待路径 | 只做了观测底座（`a327a47` 等），**优化开发未开始** | 等待位置靠日志逐轮拼，缺统一时间链 |
| P-59 分层上下文预算 | 已实现：`persona` / `fixed` 受保护，`memory` / `recent` / `ephemeral` 按 `voice` / `typed` / `fastpath` 三个入口各自配额裁剪，并报告每层丢弃量 | 默认配额宽松，只防病态长度，不是省 token 策略 |
| P-89 宿主协议门槛 | 有实时正文增量，但**没有**「已进入最终答复阶段」的协议保证，也没有可等待的正文入口 | 不能宣称 token 级首句流式；A2 用「缓冲到 step 提交」实现 |
| P-65 句内流式 | B 档（逗号切块）已实现、待审查；C 档（句内流式）未做，需先核实 GPT-SoVITS 能否增量输出 | 长句首音仍受整块合成影响 |
| 低证据门禁 | `lowEvidenceVerdict` 已有完整判定，但 `voice.lowEvidenceGate` **默认关**，只写影子 | 静音幻觉仍会投递；开启前需要更多真实设备证据 |
| 声纹身份 | CAM++ 模型、影子打分，仅麦克风通道，阈值未按本机校准；不参与投递 | 不能用于「只认主人」；误匹配风险未量化 |
| 上下文容量 | 压缩 preset 失败会降级；窗口默认 128k（无 token meter 时）；80% 只告警 | 长会话可能贴近上限，需重启或手动恢复 |
| P-128 日志噪声 | Spout 状态通道节流已提交、仍待审查 | 事件日志可能被刷到只剩约 50 分钟 |
| 透明层 | `PrintWindow` + 色键能用；移动 VTS 出屏会破坏透明推流；WGC 需原生帮助程序（P-68，条件触发） | 实验性，不适合作为稳定直播层 |
| OBS 场景截图 | `GetSourceScreenshot` 对场景返回空 | 场景模式只能走虚拟摄像头，首帧 0.5–1.5 s |
| 真机 / 真实库 | 麦克风、环境音自启、字幕字体、透明层、真实记忆库未全部复核 | 单测通过 ≠ 真机通过；发布前按 V-xx 清单复验 |
