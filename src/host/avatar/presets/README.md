# 动作预设库 v1

状态：审查中。此目录是可发布的数据和查询模块，尚未接入控制器、设置页或真实 VTS。
`package.json` 已包含 `src/host/**`，不需另改发布清单。此目录不受 `docs/` 忽略规则影响。

## 文件

- `recipes.js`：人工编写的基础编舞、能力与语义条件。
- `styles.js`：16 种风格亲和标签，允许混合；不是独占的人设类型。
- `catalog.js`：基础编舞 × 4 种节奏编排，稳定 ID 和内存索引。
- `index.js`：对外入口；`catalogStats()` 提供准确数量。

每条显示名称为「人设简称-情绪表达-相关事件-编号」，另有中文说明。
名称的首个人设是亲和标签，不限制其他人设使用。稳定 ID 采用 `recipe.variant`，
配置、历史和禁用都用 ID，不能依赖显示名或编号。
这是程序展开的编舞变体，不宣称每个变体都是完全不同的动作，也不按人设复制增加数量。

## 动作协议（实现 agent 接线依据）

`operations` 是按顺序执行的符号编舞，不是 VTS 参数名或可直接执行的脚本。
`requires` 使用当前运行时的语义通道名，必须全部经过当前模型的输入验证。
不传输模型参数名，不创建另一套参数写入者，不降级成热键。
身体、呼吸没有验证输入时，相应条目不可选；头部独立条目仍可使用。
眼睛使用 `eyeOpenL/R`，眉毛使用 `browL/R`；接线者不可擅自使用不存在的聚合通道。

操作解释：

| 操作 | 轨迹含义 |
| --- | --- |
| head-turn / head-tilt | 相对自然姿态转头／侧倾；方向由上下文和可用空间决定 |
| head-lower / head-lift | 相对自然姿态低头／抬头；方向符号由模型适配决定 |
| head-center | 头部朝当前自然基线收敛，不是数值归零 |
| head-center-lite | 仅 headX 朝当前自然基线收敛；不写 headZ，不是随机转头或数值归零 |
| nod / double-nod | 单次点头／两次点头，双次第二拍能量递减 |
| shake | 否定摇头，仅明确否定事件可选 |
| gaze-side / gaze-up / gaze-down | 从当前眼神平滑向相应方向移动，不推断外界对象 |
| gaze-target | 看向已经验证的目标；没有目标坐标不得假装注视用户 |
| gaze-center | 眼神回自然基线 |
| blink / double-blink | 眨眼／有间隔双眨；闭眼程度由模型校准，不长时间闭眼 |
| brow-lift / brow-knit / brow-one | 抬眉／皱眉／单侧眉变化，按实际绑定确定方向 |
| body-lean / body-tilt / body-settle | 身体侧移／侧倾／放松落定；不可用头部冒充 |
| breath-cycle | 一个平滑呼吸周期，不在阶段停留时憋住或截断周期 |

不把肩、手、头发、笑容列为可执行动作：当前通道协议没有这些能力。
需要新部位时扩展能力协议与对应编舞，不能只添加名称。

每个操作内部都有准备、主动作、停留、退出轨迹；复合动作按顺序启动并平滑衔接。
`flow` 连贯接续；`pause` 先短暂停顿；`linger` 到姿态后更长停留；
`spaced` 各操作之间留间隙并舒缓收尾。
瞬态操作（眨眼、点头、呼吸）必须完成周期后再停留，不能在闭眼或点头最低点僵住。
对只有一个操作的模板，spaced 表示准备/主动作/收尾之间的节奏留白。
这些均为定性节奏，具体时间从控制器和人设取得并受最大持续时间约束。

库中不设绝对幅度。现场修正读取人设、交流状态、当前姿态、已验证输入边界和受控随机，
得到幅度、方向、速度与时间；随机只在动作/阶段边界采样。超界、不可辨识或冲突时跳过。
用户说话方位必须是实际测得的，不能从普通单声道 ASR 猜声源方向。
优先保留语义：困惑不能缩小幅度后混进中性待机。

## 筛选、概率与保持不动

`queryPresets` 只做硬过滤：状态、事件、语义、能力、目标证明、禁用与隐私。
没有 state/event 返回空；不以空集合表示所有通道可用。
事件是宿主语义事件，不是词语匹配。`sentence-gap` 必须跟随实际播放；
`affirm/deny/emphasize/confused/surprised/curious/reassure/apologize/amused/uncertain/greet/farewell`
需明确交流意图。中性待机只有 `idle`，不能触发这些语义动作。

选择器由运行时实现：

1. 硬过滤后按 family 分组，给家族打分并抽取家族。
2. 在家族内选 recipe，再选 timing 变体，避免变体数量歪曲家族概率。
3. 权重参考：基础适配 × 状态适配 × 风格亲和 × 重复惩罚 × 用户有界倍率。
4. 用户优先级 0–100 默认 50，倍率 `0.25 + 1.75 * priority / 100`；禁用独立开关。
5. 设置独立的“保持当前姿态”候选，空候选直接保持；保持不发新的动作。
6. 冷却按家族和具体动作两层记录；候选不足可放松软重复惩罚，绝不放松硬条件。
7. 低频决策、高频连续插值；上限限制单位时间明显动作数量，不能每帧抽取。
8. 模型/轮次/风格/设置版本在选择及执行前复核；中断从实际姿态平滑退出。

眨眼和呼吸与已有基础生命层互斥所有权，不能两个层各自随机写。
候选输出仍需控制器检查通道占用、旧代次、速度/加速度限制和最终优先级。
queryPresets 没有承担这些运行时职责，不能把查询返回当成可直接下发的帧。

### 无 headZ/无目标的中性开口候选

新增 `answer-nod`（仅 headY，开口节奏而非赞同）、`answer-turn`（仅 headX，自然换姿态而非看向对象）、
`answer-center-lite`（仅 headX，回自然水平基线）。每类四种节奏，不依赖注视目标、声源方向或 headZ。
三类仍只接受 speaking + answer-start，不为修时序而放宽到 waiting/listening/idle。
必须绑定首段正文真实播放开始，不能由候音或后续音频块重复触发；过期不在 speechEnd 补做。
执行适配器需识别新增操作 `head-center-lite`；不认识时明确跳过并记录原因，不能回退到需要 headZ 的 head-center。
这些条目仅补能力覆盖，不修复事件暂存/释放时序。库内不增加幅度下限或直接发送参数。

## 设置页建议与持久化

第一版：搜索、按家族/风格/状态/可用性过滤；逐动作及家族启用/禁用、优先级、恢复默认、
不可用原因；用户主动预览走正常控制器。人设适配默认软降权，不永久 ban。
内置动作保持只读，“删除”存本地隐藏/禁用，可恢复。
第二版：复制为自定义、编辑、删除自定义、导入/导出受限数据文件。

用户覆盖建议存在 `<root>/data/motion-presets.json`，不写回源码，不随升级丢失：
`{schemaVersion:1, revision, families:{}, presets:{}, custom:[]}`。
内置库不是 JSON，但几百条覆盖配置使用 JSON 完全够用；原子写回、版本冲突检查。
将来需要大量自定义、审计事务再换 SQLite。Git 跟踪二进制数据库不利于审查差异。
自定义 ID 使用独立命名空间；数据严格校验通道、操作、引用和长度，不允许 eval/import 执行代码。
自定义条目同样经过全部硬过滤；普通数值编辑不能绕过语义限制。
删除或禁用正在执行的动作时平滑退出，迟到选择不得重新激活。

## 接线验收

- 验证禁用、未映射、无目标、语义不成立均零命中；隐私零动作。
- 固定候选与种子，大样本验证优先级影响概率；家族数量不因变体增多而霸占。
- 仅头部可用也有多类中性待机，候选耗尽保持安静。
- 同意图不同风格比较准备/停留/收尾，不只比较幅度。
- 连续对话、打断、切模型、设置变化和风格变化不跳变、不复活旧动作。
- 当前数据测试不等于控制器接线、用户管理界面或真机画质验收通过。
